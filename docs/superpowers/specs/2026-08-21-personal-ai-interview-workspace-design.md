# 个人 AI 面试作战台设计规格

## 1. 产品定义

本项目收敛为个人求职者使用的 AI 面试作战台。产品围绕一次具体求职目标，把岗位信息、JD、简历、面试准备、实时辅助、模拟练习、复盘和简历优化连接为一个持续闭环。

最终主流程：

```text
创建面试计划
  -> 关联岗位、JD 与简历
  -> 生成面试准备包
  -> 选择实时辅助或模拟面试
  -> 获取回答建议或逐题反馈
  -> 保存会话并生成复盘
  -> 按复盘建议继续练习或优化简历
```

产品不是企业 ATS，不以职位发布、候选人筛选、录用流程或企业协作为主线。

## 2. 产品边界

### 2.1 保留并重做

- 登录、注册和个人设置。
- 个人工作台。
- 简历上传、解析、管理和岗位匹配分析。
- 面试计划管理。
- 实时面试 Copilot。
- AI 模拟面试。
- 面试记录、报告和复盘。
- 数字人能力，作为模拟面试的可选表现形式。

### 2.2 新增并完善

- 面试准备包，包括多版本自我介绍、岗位亮点、项目追问、风险点、高频问题和 STAR 素材。
- 个人知识库，包括结构化问答、批量导入、检索、编辑、启停和索引维护。
- Copilot 会话持久化、简历/JD 上下文、问题边界、回答生成、断线恢复和错误诊断。
- 模拟面试逐题反馈、综合评分和待复习清单。
- 针对具体 JD 的简历优化建议。

### 2.3 移出个人版主线

- 企业 Dashboard。
- 职位发布和企业职位管理。
- 候选人筛选、录用和企业面试管理。
- 企业评分权重设置。

第一阶段只移除个人产品中的企业入口和导航，不物理删除企业模型、表、接口和历史数据。待个人闭环稳定并完成数据确认后，再单独制定可回滚清理方案。

### 2.4 当前不做

- 会员、支付和商业化体系。
- 企业招聘协作和多人权限体系。
- 原生移动 App。
- 自动控制或录制第三方会议软件。
- 耳机模式下自动采集第三方会议音频。
- 可靠声纹识别；首版使用手动暂停、VAD 和文本启发式降低误触发。
- 第一版直接部署重型向量数据库。

## 3. 信息架构

个人版一级导航固定为：

1. 工作台：最近计划、待准备事项、快速开始和最近复盘。
2. 面试计划：公司、岗位、JD、简历关联和准备状态。
3. 实时辅助：转写、回答要点、参考回答、追问建议和会话控制。
4. 模拟面试：面试配置、多轮问答、逐题反馈和综合报告。
5. 简历中心：上传、解析、版本管理、岗位匹配和优化建议。
6. 复盘记录：转写、回答、评分、问题分类、改进任务和导出。
7. 个人设置：账号、默认简历、模型、音频设备和知识库。

首页和认证页保留公开入口；登录后直接进入个人工作台。

## 4. 面试计划与准备包

### 4.1 面试计划

每个面试计划保存：

- 公司名称。
- 岗位名称。
- 完整 JD 与补充岗位要求。
- 关联简历。
- 技术标签、岗位级别和面试重点。
- 计划状态、最近使用时间和准备完成度。

面试计划是实时辅助、模拟面试、简历优化和复盘的统一上下文来源，不允许各模块分别维护重复的公司、岗位和简历配置。

### 4.2 准备包生成时机

创建计划并关联简历后立即生成准备包。JD、简历或岗位信息发生变化时，计划标记准备包已过期，用户可重新生成；旧版本保留用于追溯。

### 4.3 准备包内容

- 30 秒精简自我介绍。
- 60 秒标准自我介绍，作为默认版本。
- 90 秒详细自我介绍。
- 3 至 5 个岗位匹配亮点。
- 可能被追问的项目和经历。
- 简历与岗位之间的风险点。
- 高频问题和建议准备方向。
- 可复用的 STAR 故事与待补充数据。
- 从个人知识库推荐的复习主题。

自我介绍和准备内容支持编辑、复制、重新生成和标记已确认。正式开始实时辅助或模拟面试时直接读取已确认内容，不能临时阻塞启动流程。

### 4.4 事实约束

自我介绍只能重组简历、JD 和用户确认的信息，不能虚构项目、数字、职责、公司经历或技术使用经验。每项关键亮点保存来源类型和来源片段，便于用户核查。

### 4.5 自我介绍生成决策

- 创建面试计划时，只要已填写岗位/JD并关联可用简历，就自动生成准备包，其中 30/60/90 秒自我介绍是必备内容，60 秒版本作为默认展示和使用版本。
- 若计划暂未关联简历，允许先保存计划，但不生成自我介绍；页面明确提示补充简历后生成，不能只根据 JD 虚构个人经历。
- 正式开始实时辅助或模拟面试前，不重复临时调用模型生成自我介绍；直接使用最新已确认版本，未确认时允许用户继续启动，但必须显示事实核查提醒。
- JD、简历或补充要求变化后，原准备包标记为已过期，用户确认重新生成后形成新版本，旧版本保留用于复盘追溯。

## 5. 个人知识库

### 5.1 定位

知识库补充通用技术知识、回答框架和追问思路，不替代简历事实。回答上下文优先级固定为：

```text
用户真实简历与项目经历
  > 当前面试计划的岗位和 JD
  > 当前会话最近对话
  > 个人知识库
  > 模型自身通用知识
```

当简历没有相关实践时，回答必须采用“理论理解”或“如果由我设计”的口径，不能伪造成亲身经历。

### 5.2 第一版数据结构

每条知识包含：标题、问题、分类、适用岗位、技术标签、难度、核心结论、回答要点、标准回答、常见追问、易错点、来源、更新时间和启用状态。

首批分类覆盖 Java、Python、Go、MySQL、Redis、操作系统、计算机网络、数据结构与算法、微服务、分布式、系统设计、前端基础、项目场景题、行为面试、HR 面试和 STAR 表达。

### 5.3 第一版检索

第一版使用结构化字段过滤、关键词检索和轻量 BM25。查询由问题关键词、JD 技术标签、岗位级别、知识分类和难度组成，最多注入 3 至 5 条最相关内容。

只有当知识量达到数千条，或实际评测证明同义问题召回不足时，才升级为关键词检索、向量检索、元数据过滤和重排的混合 RAG。

### 5.4 维护入口

第一阶段提供 Flask 命令行：导入 Markdown、TXT、JSON，查看统计，重建索引和检查重复内容。第二阶段在个人设置中提供轻量知识库页面，支持上传、搜索、新增、编辑、禁用和重新建索引。

知识库内容应保留来源和更新时间；无来源或过期内容可以停用，不能无提示参与回答生成。

### 5.5 知识库初始化决策

- 需要在交付时预初始化一套最小基础知识库，覆盖通用面试表达、STAR 方法、行为面试和项目追问框架；它用于提升准备包、Copilot 和模拟面试质量，但不是创建计划或开始面试的硬门槛。
- 技术八股资料不整包复制来源不明的内容。首版通过项目内种子文件和 Flask CLI 导入经过筛选、注明来源与更新时间的资料，支持幂等导入、去重、停用和重建索引。
- 本产品是个人求职工具，不新增企业管理台。首版以后端 CLI 负责批量初始化和运维，个人设置中的轻量页面负责日常搜索、新增、编辑、启停和导入。
- 知识库为空或检索失败时，系统降级为“简历事实 + JD + 最近对话 + 模型通用知识”，页面提示知识增强未启用，但不能阻塞实时辅助或模拟面试。
- 只有知识规模和召回评测达到第 5.3 节所述升级条件时，才评估向量检索；最终计划不预置向量数据库、独立知识管理后台或内容爬取系统。

## 6. 实时面试辅助

### 6.1 启动条件

用户从某个面试计划启动 Copilot。会话必须关联当前用户、面试计划、简历版本和准备包版本，不再使用只有浏览器随机字符串的临时会话作为业务主键。

### 6.2 实时数据流

```text
浏览器麦克风 PCM
  -> Flask-SocketIO
  -> mica-voice ASR 网关
  -> 增量/最终转写与问题边界
  -> 简历 + JD + 最近对话 + 知识检索
  -> LLM 结构化回答流
  -> 回答要点 + 参考回答 + 追问建议
  -> 会话记录和性能事件
```

页面优先展示 3 至 5 条回答要点，完整参考回答采用可展开区域，追问建议作为次级内容。

### 6.3 状态和恢复

会话状态包括 created、running、paused、reconnecting、ended 和 error。客户端帧序列全会话严格递增，暂停恢复不能重置序列。刷新或断线后通过会话 API 恢复当前 turn、已确认转写和最近回答，不重复触发已完成问题。

### 6.4 问题边界

首版使用 ASR 最终结果、静音窗口、最小文本长度、问句特征、重复过滤和手动暂停判断完整问题。低置信度、空文本、短确认词和重复 partial 不触发 LLM，并记录误触发原因。

## 7. 模拟面试

模拟面试从面试计划启动，复用相同的上下文、知识检索和回答评估能力，不建立第二套 LLM 客户端和 Prompt。

系统按 JD、简历风险点、知识标签和面试级别生成题目结构。每轮保存问题、用户回答、参考要点、事实一致性、岗位相关性、表达结构和改进建议。结束后生成综合评分、薄弱主题、待复习清单和下一次练习建议。

数字人只作为问答展示方式之一；数字人不可用时，文本或语音模拟面试仍应正常完成。

## 8. 简历中心与优化

简历中心保存解析后的结构化事实和版本。用户选择面试计划后，系统输出岗位匹配、关键词缺口、内容顺序、项目表达和量化建议。

简历优化默认只生成修改建议和候选文本，不直接覆盖原简历。涉及新增经历或数据的建议必须要求用户确认事实，不能自动写入。

## 9. 复盘记录

每次实时辅助和模拟面试生成统一复盘：

- 会话摘要和岗位信息。
- 已确认转写和问题列表。
- 回答建议或用户回答。
- 多维评分和依据。
- 高频问题分类。
- 表达、知识和事实风险。
- 待复习知识条目。
- 下一步练习或简历优化任务。
- ASR 首字、回答首屏、完整回答和重连次数等诊断数据。

默认不保存原始音频，只保存必要文本、结构化评分和诊断事件。用户可导出文本摘要。

## 10. 视觉与交互设计

全站采用首页延伸出的深色科技工作台风格，但业务页面保持克制和高信息效率：

- 深黑灰背景、清晰表面层级、细描边和轻阴影。
- 蓝色为主操作，青色用于实时状态，紫粉只用于品牌和少量强调。
- 卡片圆角不超过 8px，避免页面区块全部卡片化。
- 统一侧边栏、顶部栏、页面标题、移动端抽屉和用户菜单。
- 表单保留可见标签、字段级错误、提交中状态和恢复建议。
- 表格在移动端转换为可扫描条目，不把横向滚动作为主要交互。
- 所有主要触控目标至少 44px，键盘焦点清晰。
- 动效控制在 150 至 250ms，并支持 prefers-reduced-motion。

响应式重点验证 375px、768px、1024px 和宽屏桌面。

## 11. 错误处理与安全边界

- 麦克风拒绝、设备断开、网络重连、ASR 不可用、LLM 超时、空结果和索引不可用必须显示原因和恢复操作。
- 外部服务调用设置超时、取消和有限重试；新问题到达时取消旧的未完成回答。
- 简历和知识文档视为不可信输入，使用明确边界分隔，不能覆盖系统指令。
- API Key、数据库地址和 Flask secret 只来自环境配置。
- 密码改用安全哈希；所有个人资源按当前用户校验归属。
- 上传路径使用项目配置和安全文件名，不依赖固定磁盘路径。
- 不在日志中输出完整简历、凭证或敏感个人数据。

## 12. 兼容与迁移策略

- 保留现有路由和字段，优先通过适配层复用旧功能。
- 新面试计划可关联现有 Resume、Job 和 AIInterview 数据，但个人计划不依赖企业发布流程才能创建。
- 旧报告可在复盘页面以只读形式展示。
- 企业端先隐藏入口，不立即删除数据库表、模型或 API。
- 重复旧页面在新流程稳定后改为重定向，再评估删除。

## 13. 测试与验收

### 13.1 自动验证

- 模型归属、状态转换和版本失效测试。
- 准备包事实约束和结构化输出测试。
- 知识导入、去重、检索、过滤和来源测试。
- Copilot PCM、序列幂等、问题边界、上下文裁剪、回答流和断线恢复测试。
- 模拟面试逐题评分和复盘生成测试。
- 关键页面、接口权限、错误路径和静态可访问性测试。
- 全量 pytest、Python 编译和 Java 网关测试。

### 13.2 人工验收

最终必须完成以下真实闭环：

1. 创建一个包含公司、岗位和 JD 的面试计划。
2. 关联简历并生成可核查的 30/60/90 秒自我介绍和准备包。
3. 从准备包进入实时辅助，完成真实麦克风转写和回答建议。
4. 从同一计划进入模拟面试，完成多轮问答和逐题反馈。
5. 查看统一复盘，并跳转到待复习知识和简历优化建议。
6. 刷新或短暂断网后恢复会话，不重复提交已完成问题。
7. 在桌面 Chrome 和目标手机浏览器验证核心路径。

性能目标：ASR 增量首字不超过 1 秒；问题结束后回答要点目标不超过 3 秒；完整参考回答目标不超过 5 秒；连续运行 30 分钟无状态卡死和重连风暴。

## 14. 实施顺序

1. 产品收敛与阻断问题修复。
2. 面试计划、准备包和个人工作台。
3. 个人知识库的命令行导入与结构化检索。
4. Copilot 会话、真实 ASR、问题边界、回答生成和恢复。
5. 模拟面试、逐题反馈和统一复盘。
6. 简历针对性优化。
7. 个人版全部页面视觉统一。
8. 数字人和专用页面适配。
9. 旧入口收敛、真实设备验证和最终验收。

## 15. 完成定义

只有当用户能够独立完成以下流程，产品才算达到本规格目标：

```text
创建面试计划
  -> 关联简历和 JD
  -> 生成并确认准备包
  -> 启动实时辅助或模拟面试
  -> 获得可追溯的回答与评分
  -> 查看复盘和待办
  -> 按建议优化简历或继续练习
```

页面存在、按钮可点击或单元测试通过，均不能单独替代上述端到端验收。

# Web UI 商业化优化计划

> 目标：消除"demo 感"，让登录后的产品达到与新版首页同级的视觉完成度。
> 原则：不换技术栈、不加重量级组件库、不动业务逻辑与 API 契约；所有升级基于现有 Tailwind v4 + shadcn 结构。

## 一、现状诊断（demo 感的来源）

1. **首页与内页断裂**：首页已是"官网级"（渐变标题、辉光、图标底色反色 hover、声波动效），登录后 13 个页面还是"毛坯级"，两套观感。
2. **组件层太薄**（`components/ui/`）：全是 shadcn 毛坯——
   - Button 无 loading 态（提交中只能改文案）、无渐变主按钮；
   - Card 只有一种平边框样式，无层次（elevated/interactive）；
   - 无 Toast（错误全靠页内红字，如 plan-list 的 `setError`）、无 EmptyState（空态是一行灰字）、无 Table、无 Progress、无 Avatar；
   - `@radix-ui/react-dropdown-menu` 已安装但零使用。
3. **页面层无视觉记忆点**：列表是纯文字行（workspace 的计划列表：两行字 + badge）；无统计卡、无进度可视化、无图标层次；表单是 label+input 裸堆叠。
4. **壳层简陋**（`app-shell.tsx`）：侧栏无用户身份区、无导航分组、无折叠；顶栏除了主题切换是空的。
5. **视觉语言单一**：满屏 1px 平边框，无阴影分级、无品牌色 moment、无微交互。

## 二、设计语言定义（从首页反向统一到全站）

- **色**：primary 青绿 `--primary` → accent 天蓝渐变，仅用于品牌 moment（主 CTA、标题强调、进度）；语义色 success/warning/destructive 各自 soft 底 + 实色点。
- **形**：圆角三档（6/10/14px），卡片 `rounded-xl`；边框只做静态分层，悬浮态一律"边框变 primary/40 + translateY(-2px) + shadow-md"。
- **层次**：背景 `< 卡片 < 浮层` 三级；阴影仅浮层与 hover 用（避免平框感的关键是阴影分级，不是加边框）。
- **图标**：lucide 统一，功能位固定——图标一律放进 `size-10 rounded-lg bg-primary-soft` 底座，hover 反色（沿用首页能力卡的处理）。
- **动效**：150ms 颜色 / 200ms 位移；列表入场 stagger 30ms/项；`prefers-reduced-motion` 全局降级已有，保持。

## 三、分阶段执行

### P0 组件库商业化改造（地基，约 1.5 天）

| 组件 | 改造内容 |
|---|---|
| tokens (`index.css`) | 补 `--shadow-xs/sm/md/lg` 四级、`--gradient-brand`、`--glow`（辉光） |
| Button | +`loading` prop（转圈图标+禁用）；+`gradient` variant（主 CTA 专用）；focus ring 统一 |
| Card | cva 三档 variant：`default`（现样式）/ `elevated`（shadow-md）/ `interactive`（hover 升起+描边亮） |
| Toast（新增） | 轻量自研（zustand store + 固定定位栈），success/error/info 三态，替代各页 `setError` 红字 |
| EmptyState（新增） | 图标底座 + 标题 + 描述 + 行动按钮，替代"一行灰字"空态 |
| StatCard（新增） | 数值 + 标签 + 趋势位，工作台/复盘用 |
| Progress（新增） | 细条进度，准备包生成/评分用 |
| Avatar（新增） | 公司/用户首字头像（带底色 hash），列表立即"活" |
| Tooltip / DropdownMenu（新增） | 封装已装的 radix 包，icon 按钮提示与行内操作菜单用 |

**验收**：所有新组件在暗/亮主题下截图过目；Button loading 在任一表单实际接入。

### P1 应用壳升级（约 1 天）

- 侧栏：品牌区（logo 底座 + 渐变字）→ 导航分组（`实战`：工作台/计划；`资产`：简历/知识库/复盘；`设置`：个人设置）→ 底部用户卡（Avatar + 邮箱 + 退出菜单）；
- 顶栏：左侧当前页上下文（面包屑一级即可），右侧主题切换 + 快捷「新建计划」；
- 移动端：横滚导航保留，退出移入用户 Sheet。

**验收**：1440px 与 390px 两档截图；导航分组后不超一屏。

### P2 高频动线页面改造（约 2.5 天）

按用户动线顺序，每页先布局后细节：

1. **工作台**：顶部欢迎条（问候 + 今日待办）→ 4 张 StatCard（计划数/待复习/复盘均分/简历版本）→ 四入口卡升级为 interactive 卡（图标底座 + hover 反色，对齐首页）→ 计划列表行加 Avatar + Progress。
2. **计划列表**：卡片网格替代表格行——公司 Avatar + 公司/岗位 + 技术标签组 + 状态色条 + hover 升起；新建弹窗表单分组（基本信息/JD/标签）。
3. **计划详情**：准备状态用 Progress + 时间线；参考回答、要点区沿用 copilot 卡片语言。
4. **复盘列表/详情**：复用首页 ScoreRing 展示评分；风险点用 warning-soft 卡。

**验收**：四条动线走查（建计划 → 生成 → 实战 → 复盘）无一行"纯文字列表"；每页有至少一个品牌 moment。

### P3 表单与反馈闭环（约 1 天）

- 登录/注册：左品牌右表单分栏（品牌区放渐变标语 + 声波装饰），移动端上下堆叠；
- 全部提交按钮接 `loading`；接口错误 → Toast（页内仅保留表单校验红字）；
- 危险操作（归档、删除、结束面试）统一 Dialog 确认样式（destructive 主按钮）。

**验收**：断网/报错场景走查，反馈全部有 Toast 或行内校验，无静默失败。

### P4 实时双页打磨（约 1.5 天）

- **实时辅助 (copilot)**：转写气泡按说话人视觉分级（我=primary-soft 右侧 / 面试官=subtle 左侧，对齐首页演示面板）；回答要点改为带图标底座的卡片流；参考回答区加"流式输出"角标与打字光标；连接状态徽章沿用 landing 的呼吸灯。
- **模拟面试**：逐题评分用 Progress + 分数；综合评分用 ScoreRing。

**验收**：实战走查 10 分钟无视觉疲劳点；动效在 reduced-motion 下静止但不缺失信息。

### P5 全局细节走查（约 1 天）

- 列表入场 stagger、页面切换淡入（150ms）；
- 骨架屏统一为卡片形状（现在是两根光条）；
- favicon、`document.title` 按页设置、暗/亮全量截图走查、键盘焦点环走查。

## 四、执行顺序与工作量

| 阶段 | 内容 | 估时 | 依赖 |
|---|---|---|---|
| P0 | 组件库改造 | 1.5d | 无 |
| P1 | 应用壳 | 1d | P0 |
| P2 | 高频页面 | 2.5d | P0、P1 |
| P3 | 表单反馈 | 1d | P0 |
| P4 | 实时双页 | 1.5d | P0、P1 |
| P5 | 细节走查 | 1d | 全部 |

合计约 **8.5 天**；若先只做"P0+P1+工作台/计划列表"核心包（约 4 天），观感提升即可覆盖 80% 日常动线。

## 五、明确不做

- 不引入 antd/mui 等重组件库，不换 Tailwind/shadcn 结构；
- 不改 API 契约与业务逻辑（纯视觉与交互层）；
- 不做插画系统（用图标底座 + 渐变/辉光替代，避免维护成本）；
- 不动实时辅助的信息架构（转写/要点双栏已验证可用，只做视觉升级）。
